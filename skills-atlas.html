A field catalog of the Claude-Skills collection

Many skills.
Few tokens.

Sixty-two skills from four origins, every one paying rent in one of three load tiers, now split into nine suites you install separately. The catalog, the economics that govern it, and what was deliberately kept out.

Repo: YogirajA/Claude-Skills [1] · suites from mattpocock/skills [2], JuliusBrussee/caveman [3] and affaan-m/ECC [4]; archify from tt-a1i/archify [5].
Snapshot 2026-09-07.

A skill is the smallest unit of packaged judgment in Claude Code: a folder, a SKILL.md with YAML frontmatter, and whatever reference files the body reads on demand. The description in the frontmatter is what the model sees every session; the body loads only when the skill fires. That two-line mechanical fact turns out to govern everything else about running a collection of fifty-six of them.

This atlas catalogs the collection as of September 2026: 34 hand-typed originals, 14 adapted from Matt Pocock's engineering suite, 8 from the Caveman token-economy project, and 6 from ECC's harness-measurement layer, plus two diagram skills vendored from ccc and tt-a1i/archify, and three compressed subagent presets riding along with cavecrew. Every import was filtered the same way: standalone over infrastructure-coupled, distinct over duplicate, and nothing whose licence forbids an MIT collection.

“Every skill leaks a description into the context window. A hundred skills means a hundred descriptions loaded whether or not you use them.” Matt Pocock, David Ondrej interview, Jun 2026

What each line costs

The three load tiers

Lines of code in a skill are not one number. They are three numbers, and only one of them is paid unconditionally.

Tier 1: description every session
The frontmatter description loads into every conversation, used or not. At 60 to 340 tokens each, 56 descriptions cost roughly 8.4k tokens before the first prompt, and 62 cost 9.1k (measured with claude plugin details, not estimated). This is the tier to guard: a skill that never fires still bills here forever. disable-model-invocation: true zeroes it for user-only skills.
Tier 2: SKILL.md body on invoke
Loads when the skill fires. Costly only if bloated: onboard-repo's body is ~3,400 tokens and delegates everything heavy to references. The house rule that fell out of building it: every phase is 10 to 30 lines and points at a reference file, never 90 lines inline.
Tier 3: references only if read
Free until opened. onboard-repo carries ~14k tokens of interview scripts, hook library, and templates at zero standing cost. This is where depth belongs: the tier explains why a 40-line wrapper plus fat references beats one fat SKILL.md.
The governing rule, from three independent sources: config and skills you have not earned get ignored or actively hurt. Boris Cherny deletes his CLAUDE.md, skills, and hooks every six months and re-adds on repeated failure only. Pocock deletes everything and watches the bare agent. Anthropic's docs name “the over-specified CLAUDE.md” as a failure pattern. The collection's answer is provenance: every import below records where it came from, what it duplicates, and what was refused.

Origin three · 8 skills + 3 agents

The Caveman token-economy suite

“Why use many token when few do trick.” The only tools in the collection that cut the output side of the meter, where a token costs five times what an input token does ($50 vs $10 per MTok on Claude Fable).

Style engineTerse mode and its craft

Not mere brusqueness: the rules are tokenizer-aware. Invented abbreviations are banned because the tokenizer splits cfg and impl anyway (zero saved, harder to read). Arrow glyphs are banned because they are their own token. Grammar survives wherever mangling is token-neutral. Negations, numbers, code, and error strings are always exact.

cavemanUltra-compressed output mode: lite / full / ultra, plus wenyan variants. Fluff dies, substance stays, session-persistent until “stop caveman”
caveman-compressUOApplies the style to stored context: compresses a CLAUDE.md or memory file with a readable backup, moving savings to the input side of the meter
caveman-helpUOQuick-reference card for the modes and skills
Delegationcavecrew and the subagent tax

Subagent tool results land in the main context verbatim: a vanilla Explore returning 2k tokens of prose costs 2k tokens of main-context budget every delegation. The three presets return the same findings compressed, roughly a third of the tokens across twenty delegations.

cavecrewThe routing guidance: when to reach for a compressed preset vs vanilla Explore vs main thread
cavecrew-investigatorAgent preset: read-only locator, file:line table out, refuses to suggest fixes
cavecrew-builderAgent preset: surgical 1-2 file edit, hard-refuses 3+ file scope, diff receipt out
cavecrew-reviewerAgent preset: one line per finding, severity-tagged, no praise, no scope creep
caveman-exploreHaiku-powered read-only explorer, citations only, parallel fan-out on the first turn
DisciplineThe task-shape trio

Sixteen-line skills, each naming one task shape and its stop condition. The smallest well-made skills in the collection.

safe-refactorRestructure while preserving behavior; verification brackets every structural edit
surgical-patchFix at the narrowest responsible layer, regression proof, surrounding behavior preserved
migrationReversible, compatibility-safe transitions: schema, data, API, config, dependency
Honest numbers
The rules cost ~1,250 input tokens per turn

Documented by the project itself: terse-mode rules are injected every turn, so net savings go negative on short sessions. Their own stats output prints the net and says so plainly rather than hiding it behind gross savings. Pays on long, output-heavy sessions; not an always-on default.

Pipeline position
A new row in the token-reduction table

The wiki's comparison now holds five stages: the wiki cuts re-derivation (write-time), /compact cuts history (session), Headroom and RTK cut payloads (I/O boundary), Graphify cuts codebase-reading (retrieval), and Caveman cuts the model's own prose (generation). Same boundary as RTK, opposite direction.

Origin four · 6 of 286 offered

The ECC harness-measurement suite

affaan-m/ECC ships 286 skills. Holding all of them would cost roughly 30,000 always-on tokens, more than three times this whole collection, to buy skills like cisco-ios-patterns and homelab-pihole-dns. Six were taken, for 770.

MeasureTools that audit the setup, not the code

The theme: stop trusting the harness and start measuring it. Every other section here is about doing work; this one is about whether the machinery doing it is sound.

loop-design-checkThe judgment layer for agent loops: a four-condition veto on building one at all, a machine-decidable goal test, servo vs regulator typing, five named failure modes, three red lines
skill-complyMeasures whether a skill or rule is actually obeyed: scenarios at three prompt-strictness levels, real claude -p runs, tool traces classified and ordered
context-budgetAudits agents, skills, rules, MCP tool schemas and the CLAUDE.md chain; ranks fixes by tokens reclaimed
config-gcGarbage collection over ~/.claude: stale, orphaned, redundant, low-value, with confirm-each deletion
gateguardThree-stage fact-forcing gate: deny the first edit, force named facts, allow the retry. Imported as a design, not a runnable hook
skill-scoutSearch local, marketplace, GitHub and web sources before writing a new skill
The load-bearing part
Each one starts by telling you what to delete

The references open with a subtract table, not an add list. Opus 5 over-verifies when told to verify; Sonnet 5 under-reports when told to be conservative; Fable 5.1 goes quiet when told to hold findings for the end. Newer models invert the advice older prompts were built on, so removing beats adding.

Vendoring policy
Copied in, never depended on as a plugin

ECC is a plugin marketplace, and plugins here are installed only from Anthropic's repos or my own. So the useful parts are vendored under their licence with provenance in the frontmatter, and the marketplace is not installed. excalidraw came from ooiyeefei/ccc the same way, after that marketplace was removed, and archify from tt-a1i/archify, with its phone-home update checker cut out before install.

How it is actually installed

Nine suites, not one plugin

The repo is a plugin marketplace. Two manifest files turn it from “copy the folder” into an install command, and the split into suites is the tier-1 economics applied to its own packaging.

claude plugin marketplace add YogirajA/Claude-Skills
claude plugin install kb-wiki@yogi-skills
claude plugin details harness-audit@yogi-skills   // price it before installing

Shipping one 62-skill plugin would put the full standing cost on every repo you open, including qa-deck while you debug a hook. A suite is the unit you actually want on or off.

How these numbers were measured, and a correction. They are claude plugin details output, or raw chars÷4 scaled by the 1.49 factor calibrated against it. An earlier draft of this page used the raw estimate and “corrected” the tier-1 figure down to 4.5k. The CLI then reported 770 where chars÷4 predicted 517, a ratio that held between 1.46 and 1.61 across six skills, which put the original 8-to-10k claim back where it started. The estimator you reach for first is the thing to check.

The filter, stated once: a skill earns import only if it is standalone (no vendor gateway, no bespoke hooks), distinct (no same-name shadowing, no duplicate of an installed process skill), and licensed for an MIT collection. Everything that passed is above; everything that failed is here.

The through-line

A collection is a budget, not a library.

Every skill pays tier-1 rent every session, whether it fires or not. So the discipline that governs the collection is the same one that governs a CLAUDE.md, a harness, or a prompt: import on demonstrated need, record the justification, schedule the review, and let removal be the default answer when the justification no longer holds.

need repeats→ import or write→ record why→ review in six months→ delete freely

The refusals section exists because the noes decay faster than the yeses: nothing re-proposes a skill you have, but everything re-proposes a skill you declined, unless the reason is written down.
